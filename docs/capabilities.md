## Protocol messages and events

| Transport                              | Contract                                                                                            | Implementation / disposition                                                             |
| -------------------------------------- | --------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| `/api/ws` binary `0x00`                | Firmware heartbeat, aiohttp also handles WebSocket ping/pong                                        | `events`, bounded reconnect in coordinator, fresh read after opening                     |
| `/api/ws` binary `0x01` + 8 bytes      | Modifier, reserved byte, six HID usages                                                             | `send_keys`, release on same connection                                                  |
| `/api/ws` binary `0x02` + 4 or 6 bytes | Buttons, signed relative x/y or little-endian absolute x/y, signed wheel                            | `mouse`, release pressed buttons                                                         |
| `capture-status`                       | JSON string in envelope data, ok/result/message/mode/severity/updatedAt                             | Typed `CaptureStatus`, state sensors, private message never exposed                      |
| `h264-mode-status`                     | generation/revision/direct/webrtc/mixed                                                             | Typed `VideoClients`, conflict state only, because counts are not continuously broadcast |
| `hid-led-status`                       | numLock/capsLock/scrollLock/known/updatedAt                                                         | Typed `KeyboardLeds`, unknown remains unknown                                            |
| MJPEG                                  | HTTP multipart JPEG frames, shared encoder                                                          | `jpeg`, explicit preview consent                                                         |
| Direct H.264                           | WebSocket binary frames with a keyframe byte and eight-byte little-endian timestamp, shared encoder | `open_direct_h264`, standalone transport/native console                                  |
| WebRTC signaling                       | WebSocket event/data strings: video-offer, video-answer, video-candidate, ice-servers, heartbeat    | `open_webrtc`, feed a standard WebRTC implementation, native console in HA               |
| Terminal                               | WebSocket text input, binary shell output, binary JSON rows/cols resize control                     | `open_terminal`, native UI only                                                          |
| PicoClaw gateway                       | Native WebSocket JSON gateway frames                                                                | `open_picoclaw_gateway`, native UI only                                                  |
| MCP                                    | Standard MCP HTTP protocol, bearer API key                                                          | Standard MCP client, native configuration retained, no custom protocol framework         |

Protocol transport tests cover framing, heartbeat, malformed/unknown messages, connection errors and cleanup. Full interactive terminal, WebRTC media negotiation, PicoClaw conversation and MCP tool execution are delegated to their native/standard clients and have not been exercised live.

The stable [MCP tool schema](https://github.com/sipeed/NanoKVM/blob/2.5.2/server/service/mcp/server.go) exposes six tools through its authenticated standard protocol:

| Tool                | Parameters                                                      |
| ------------------- | --------------------------------------------------------------- |
| `cube_type_text`    | `text`, `delayMs`                                               |
| `cube_press_keys`   | `keys` (KeyboardEvent.code names), `holdMs`                     |
| `cube_move_mouse`   | `mode`, normalized absolute `x`/`y`, relative `deltaX`/`deltaY` |
| `cube_click_mouse`  | `button`, `clicks`, `mode`, `x`, `y`                            |
| `cube_scroll_mouse` | `deltaY`                                                        |
| `cube_screenshot`   | `quality`, `timeoutMs`                                          |

MCP clients discover the firmware's exact schemas and limits at runtime. These tools remain available through standard MCP clients. The HA input actions use the device's direct APIs.

## Exclusions and firmware limits

- Loopback-only `/api/internal/usb/recover` and PicoClaw screenshot/actions/MCP/load-image/runtime-session reads require an internal token and are not external device capabilities.
- Browser-only display/layout/theme/preferences are not device settings. Native persisted shortcut and web-title APIs are nevertheless covered above.
- Pro APIs, development-only auth/storage events and newer APIs are excluded.
- USB `media` is a dummy false field. `disk` means raw data-partition sharing, not all mounted USB media.
- Firmware gadget changes toggle state. Another controller can race read–compare–toggle–read. Empty image mount attaches the raw partition, not an eject.
- MJPEG access itself can switch the native encoder. Consent is required even without an explicit encoding command.
- H.264 counts only broadcast when mixed-mode conflict changes. Continuously accurate viewer-count entities are intentionally absent.
- OLED sleep 0–3600 seconds is the HA number range. Firmware accepts a broader integer field.
- FPS below ten and unrecognized quality values are silently substituted by firmware. Client actions reject them.
- Standard user permissions are validated at the device, and admin-only entities do not block power monitoring.
